# MQTT 会话网关（进程内模拟）

本工程实现一套本地可验证的 MQTT 风格设备消息网关：用进程内的连接与订阅状态
模拟设备接入，保证不同会话、QoS 与并发场景下的投递结论一致且可解释。
核心代码位于 `com.github.h3yow.mqttsessiongatewayjava.gateway` 包，不依赖任何外部服务。

## 主题匹配规则

- 主题与过滤器均以 `/` 分层，空层级（`a//b`、首尾 `/`、空串）非法。
- `+` 匹配**恰好一层**，且必须独占一层（`a/+/c` 合法，`a/b+` 非法）。
- `#` 匹配**其自身及之后所有层（含零层）**，必须独占一层且只能位于最后一层
  （`a/#` 合法，`a/#/b`、`a#` 非法）。
- 发布主题不得包含通配符。
- 非法输入抛出 `GatewayException`，原因可区分：
  - `FILTER_EMPTY_LEVEL`：过滤器为空或含空层级；
  - `FILTER_WILDCARD_MISPLACED`：通配符未独占一层或 `#` 不在最后一层；
  - `TOPIC_INVALID`：发布主题为空、含空层级或含通配符。
- 路由只把消息投递给过滤器匹配的订阅；同一会话多条订阅命中同一主题时只投递一次。

## 投递与确认语义

- **QoS.AT_MOST_ONCE（至多一次）**：在线投递即完成，不跟踪、不需确认；
  离线时进入持久会话积压，重连后补投一次。
- **QoS.AT_LEAST_ONCE（至少一次）**：在线投递后登记为待确认（在途）；
  未确认的消息在客户端重连时按原 messageId 重投，直到被确认为止。
- **持久会话**：`connect(clientId, true)` 创建；断开后保留订阅、离线积压与待确认，
  重连时 `connect` 返回需补投的消息列表（离线积压 + 未确认消息），不丢不重。
  非持久会话断开即清除全部状态。
- **确认（ack）**：
  - 确认成功：消息从待确认与在途集合移除；
  - 重复确认：拒绝，原因 `ACK_DUPLICATE`；
  - 非对应订阅者的确认（含未知 messageId）：拒绝，原因 `ACK_NOT_PENDING_FOR_CLIENT`；
  - 会话不存在：拒绝，原因 `SESSION_NOT_FOUND`。

## 容量与背压

配置项（`application.properties`，前缀 `gateway`）：

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| `gateway.backlog-capacity` | 1000 | 单会话离线积压上限。任一目标会话积压满时，发布被整体拒绝（`BACKLOG_CAPACITY_EXCEEDED`），不会部分投递，也不会静默丢弃。 |
| `gateway.max-in-flight` | 10000 | 全网关在途（已投递待确认）消息上限。达到上限时发布被限流拒绝（`BACKPRESSURE_LIMIT_EXCEEDED`），确认后释放额度。 |

所有操作均为内存操作且在单把锁内原子完成：慢客户端只会触发对自己的
明确拒绝，不会阻塞其他客户端的发布、订阅与确认。

## 并发一致性

路由判定与投递状态变更在同一临界区内生效，因此多线程并发发布/订阅/确认时，
同一主题的每次路由结果都是一致快照：匹配订阅者无遗漏、无重复、无不匹配者。
确认恰好一次生效，并发重复确认全部被识别为 `ACK_DUPLICATE`。

## 本地验证

无需任何外部服务，直接构建并运行测试：

```bash
mvn test
```

测试覆盖（日志会打印输入、会话状态与投递判定依据）：

- `TopicFilterTest`：通配符边界（`+`/`#`、混合、零层匹配）与非法过滤器/主题的可区分拒绝；
- `DeliveryAckTest`：路由不投递给不匹配订阅、两种 QoS 语义、重复确认与错误订阅者确认的可区分拒绝；
- `OfflineBacklogTest`：持久会话离线积压、重连补投不丢不重、积压超容量拒绝、背压限流；
- `ConcurrencyTest`：16 线程并发发布路由一致性、并发确认恰好一次、慢客户端明确拒绝且不阻塞网关。
