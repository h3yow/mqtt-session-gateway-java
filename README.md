# MQTT 会话网关（进程内模拟）

本工程实现一套本地可验证的 MQTT 风格设备消息网关：用进程内的连接与订阅状态
模拟设备接入，保证不同会话、QoS、容量背压、并发与**进程重启**场景下的投递结论
一致且可解释。核心代码位于
`com.github.h3yow.mqttsessiongatewayjava.gateway` 包，不依赖任何外部服务
（持久化仅使用本地文件）。

## 主题匹配规则

- 主题与过滤器均以 `/` 分层，空层级（`a//b`、首尾 `/`、空串）非法。
- `+` 匹配**恰好一层**，且必须独占一层（`a/+/c` 合法，`a/b+` 非法）。
- `#` 匹配**其自身及之后所有层（含零层）**，必须独占一层且只能位于最后一层
  （`a/#` 合法，`a/#/b`、`a#` 非法）。
- 发布主题不得包含通配符。
- 非法输入抛出 `GatewayException`，原因可区分：
  - `FILTER_EMPTY_LEVEL`：过滤器为空或含空层级；
  - `FILTER_WILDCARD_MISPLACED`：通配符未独占一层或 `#` 不在最后一层；
  - `TOPIC_INVALID`：发布主题为空、含空层级或含通配符。
- 路由只把消息投递给过滤器匹配的订阅；同一会话多条订阅命中同一主题时只投递一次。
  路由结果按会话连接登记顺序返回（顺序稳定，便于排查）。

## 投递与确认语义

- **QoS.AT_MOST_ONCE（至多一次，QoS0）**：在线投递即完成，不跟踪、不需确认；
  离线时进入持久会话积压，重连后补投一次（补投即完成）。
- **QoS.AT_LEAST_ONCE（至少一次，QoS1）**：在线投递后登记为待确认（在途）；
  未确认的消息在客户端重连时按原 messageId 重投，直到被确认为止。
- **持久会话**：`connect(clientId, true)` 创建；断开后保留订阅、离线积压与待确认，
  重连时 `connect` 返回需补投的消息列表（离线积压 + 未确认消息），不丢不重。
  非持久会话断开即清除全部状态，且**从不落盘**。
- **确认（ack）**：
  - 确认成功：消息从待确认与在途集合移除，并记入该会话的有界"已确认"集合；
  - 重复确认：拒绝，原因 `ACK_DUPLICATE`（重启后仍可识别）；
  - 非对应订阅者的确认（含未知 messageId）：拒绝，原因 `ACK_NOT_PENDING_FOR_CLIENT`；
  - 会话不存在：拒绝，原因 `SESSION_NOT_FOUND`。

## 发布侧 QoS 与双边协商

- 发布可显式指定 QoS：`publish(topic, payload, qos)`；不带 QoS 的
  `publish(topic, payload)` 重载等价于按 `AT_LEAST_ONCE` 发布（兼容旧行为）。
- **每条投递的实际（协商）QoS = min(发布方 QoS, 订阅方 QoS)**：
  一边只保证至多一次，整条投递就按至多一次。例如订阅方要 QoS1、发布方只给 QoS0，
  则该投递按 QoS0 执行：在线不进在途、不要求确认；离线积压在补投时也按 QoS0
  补投即完成，不会补投后又要求确认。
- 协商结果在发布当时算定并随离线积压条目一起持久化，重连补投与确认都按
  协商后的等级执行，而不是发布、订阅各算各的。
- QoS0 投递不占用在途额度：全网关在途打满时，纯 QoS0 发布仍可被接受。

## 重启恢复（本地持久化）

- 配置 `gateway.data-dir` 指向一个本地目录后，网关把所有状态变更以
  **JSONL 追加日志**（`<data-dir>/journal.jsonl`）写入本地文件；留空则为
  纯内存模式（默认，便于测试），进程重启不恢复。
- **恢复范围（仅持久会话）**：订阅、离线积压（含每条协商后的 QoS）、
  已投递未确认的消息（恢复后仍计入全网关在途）、最近已确认 messageId 集合、
  全局 messageId 水位（重启后新消息 id 继续向后分配，不与历史消息冲突）。
  恢复出的会话一律为离线状态，等待对应客户端重连后照常补投：不丢、不重，
  已确认过的消息不会重新冒出来；非持久会话重启后彻底不存在。
- **持久化时机与原子性**：一次操作内的多条状态变更（例如重连时积压条目
  "移除积压 + 登记待确认"）打成一个批次一次写入并 `fsync`，崩溃不会出现
  只完成一半的中间态。`Gateway.close()`（Spring 关停时自动调用）会刷盘并
  关闭文件句柄。
- **快照压缩**：每次网关启动先重放日志恢复状态，随即把当前全量状态写成一行
  快照、原子替换旧日志，防止日志无限增长；崩溃残留的截断尾行会在重放时被
  跳过并打印告警。
- 存储实现见 `gateway/persist`：`GatewayStore` 接口、`LocalFileGatewayStore`
  （文件）与 `MemoryGatewayStore`（空实现）。

## 容量与背压

配置项（`application.properties`，前缀 `gateway`）：

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| `gateway.backlog-capacity` | 1000 | 单会话离线积压上限。任一目标会话积压满时，发布被整体拒绝（`BACKLOG_CAPACITY_EXCEEDED`）。 |
| `gateway.max-in-flight` | 10000 | 全网关在途（已投递待确认）消息上限。接受发布后会使在途超过上限时，发布被限流拒绝（`BACKPRESSURE_LIMIT_EXCEEDED`），确认后释放额度。 |
| `gateway.data-dir` | 空（纯内存） | 本地数据目录；配置后启用重启恢复。 |

严格语义：

- 一次发布先完成**无副作用的路由判定**，再按各目标协商后的 QoS 统计本次将
  新增的在途数量：`现有在途 + 新增在途 > max-in-flight` 即整体拒绝；
  随后分配 messageId 并做各离线目标的积压预检，任一目标
  `backlog >= backlog-capacity` 也整体拒绝。
- 因此**任何被接受的发布都不会让实际统计到的积压量或在途量超过各自上限**；
  被拒发布在产生任何投递之前中止：不会投一半留一半（即使部分目标尚有额度），
  积压满也不会静默丢消息，只给出携带明确原因的拒绝。
  （恰好等于上限时发布仍可被接受。）
- 所有操作均在单把锁内原子完成，且只操作内存状态：某个设备把自己的积压或
  在途额度占满，只会触发对**它自己相关发布**的明确拒绝，不会阻塞或连累
  其他设备的发布、订阅与确认，更不会卡住整个网关。

## 并发一致性

路由判定与投递状态变更在同一临界区内生效，因此多线程并发发布/订阅/确认时，
同一主题的每次路由结果都是一致快照：匹配订阅者无遗漏、无重复、无不匹配者。
确认恰好一次生效，并发重复确认全部被识别为 `ACK_DUPLICATE`。
启用持久化时，文件追加同样发生在这把锁内，单进程内写入串行、结论可重放。

## 运行时日志

关键操作均以 INFO 级别记录输入与判定依据，便于逐步排查：

- `[connect]` / `[disconnect]`：客户端、是否持久会话、订阅数、积压/待确认数量与补投 id；
- `[subscribe]`：过滤器与订阅 QoS；
- `[route]`：每条投递的会话在线状态、发布 QoS、订阅 QoS、协商结果
  （"登记在途/进入积压/投递即完成"）；
- `[publish]`：messageId、主题、payload、发布 QoS、路由结果与当前在途数；
- `[ack]` / `[ack-reject]`：确认生效或拒绝原因；
- `[restore]` / `[replay]` / `[compact]`：重启恢复出的会话数、messageId 水位与日志压缩。

## 本地验证

无需任何外部服务（持久化用临时目录或 `data/gateway`，无需数据库/消息中间件）：

```bash
mvn test
```

测试覆盖：

- `TopicFilterTest`：通配符边界与非法过滤器/主题的可区分拒绝；
- `DeliveryAckTest`：路由、两种 QoS 语义、重复确认与错误订阅者确认；
- `OfflineBacklogTest`：同进程离线积压、重连补投、积压容量拒绝、**严格在途上限**
  （超上限整体拒绝、恰好等于上限可接受）；
- `PublishQosNegotiationTest`：发布侧 QoS、min() 协商、协商结果决定在途/确认/补投、
  QoS0 不占在途额度；
- `CapacityIsolationTest`：积压/在途统计绝不越界、超限发布零投递整体拒绝、
  一个设备占满额度不连累其他设备；
- `RestartRecoveryTest`：**真正关闭网关并 new 一个新实例指向同一数据目录**
  （`@TempDir`），验证订阅/积压/未确认/已确认记录/消息 id 水位跨进程恢复、
  非持久会话重启消失、协商 QoS 随积压恢复、启动快照压缩；
- `LocalFileGatewayStoreTest`：追加/重放、快照压缩、崩溃残缺尾行容错；
- `ConcurrencyTest`：16 线程并发发布路由一致性、并发确认恰好一次、
  慢客户端明确拒绝且不阻塞网关；
- `PersistentConcurrencyTest`：启用持久化时 8 线程并发发布/落盘，关闭后新实例
  重放的待确认与在途统计与关闭前完全一致（不丢、不重）。

以持久化模式手工体验（可选）：默认配置已启用 `gateway.data-dir=data/gateway`，
通过 Spring Boot 启动后正常停止（让其 `close()` 刷盘），再次启动即可观察到
`[restore]` 恢复日志；删除该目录即回到全新状态。
